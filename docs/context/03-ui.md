# 03 — UI

## Summary

Full budgeting UI implemented as a single-page spreadsheet-inspired layout. Covers all 10 tasks: dashboard layout, year summary bar, 12-month grid, entry lists, inline-editable rows, add/edit dialog, balance indicators, category visualization, quick actions (duplicate/delete), and warning/success states.

## Key Decisions

- **Two-panel layout** — left sidebar holds the 12-month grid; clicking a month opens a detail panel on the right. No routing, no tabs, pure local state (`selectedMonth`).
- **Inline amount editing** — clicking an amount in `EntryRow` activates an `<input>` in-place. On blur/Enter the value is committed as an override; if it matches the base amount the override is removed automatically.
- **Override indicator** — overridden amounts render in yellow with a ↺ badge; clicking the badge removes the override and reverts to the base value.
- **No Bits UI for the dialog** — plain `<div role="dialog">` with backdrop click + Escape to close. Keeps it minimal; Bits UI not needed for one simple modal.
- **Import uses `replaceBudget`** — full DB clear + replace on import, consistent with the spec.
- **Category datalist** — native `<datalist>` for autocomplete suggestions; no extra dependency.
- **Duplicate entry** — copies the entry with a `(copy)` suffix via `onAddEntry`; no new mutation function needed.

## Data Model Changes

None. All types from phase 01 and mutations from phase 02 remain unchanged.

## Constraints

- `selectedMonth` state lives in `BudgetDashboard` — do not lift to `+page.svelte`
- Dialog state (open/editEntry/defaultType) lives in `BudgetDashboard` — same reason
- Override reset logic: if new amount ≈ base → `removeOverride`; otherwise `setOverride`
- `replaceBudget` is called only from `ImportExportMenu` on confirmed import — `saveBudget` remains the autosave path
- No new dependencies introduced
